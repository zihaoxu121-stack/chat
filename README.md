# 聊天话术助手 · Windows 客户端

[下载安装包（预览版）](https://github.com/zihaoxu121-stack/chat/releases/tag/v1.0.1) · [查看自动构建进度](https://github.com/zihaoxu121-stack/chat/actions/workflows/windows.yml)

1.0.1 修复 Windows 中文快捷方式乱码及错误启动路径。新版会替换本程序的旧乱码快捷方式，聊天数据保持不变。

适用：64 位 Windows 10 / 11。安装包自带运行环境，不需要 Node.js、Python 或本地模型，不需要命令行。程序不连接聊天账号，也不代发消息。

## 开始使用

1. 双击 `ChatDraft-Setup-1.0.1-x64.exe`，安装完成后启动。程序安装到当前用户的 `%LOCALAPPDATA%\Programs\ChatDraftAssistant`，不要求管理员权限。
2. 打开“模型与设置”，填写 API Base URL、API Key、支持图片输入的模型名，以及“本人真实信息”（可从最初需求中的本人档案复制）。本人档案只保存在本机，不放在公开源码中。Base URL 通常以 `/v1` 结尾，不要填写完整的 `/chat/completions`；程序会拼接该路径。兼容接口必须接受标准 OpenAI Chat Completions 的文字和 `image_url` 数据 URL 输入。程序通过提示词要求 JSON，不依赖原生 `response_format` 功能。
3. 在工作台粘贴或拖入截图；也可以粘贴文字。文字建议按每条消息一行写“我：”“对方：”，不改动错别字。
4. 点击识别后，对照截图核对平台、联系人和消息归属。认不准时手选，缺少档案时点击“新联系人，建立档案”。即使匹配成功也保留确认步骤。同平台同名多人不会自动选人。
5. 勾选确认后生成三版。每版两气泡，各自复制；整版复制用单个换行连接气泡，无空行、版号或项目符号。
6. “再来一版”基于该轮已保存的输入和档案快照，仅追加一版，不覆盖旧稿。更换截图或聊天对象，使用“新建一轮”。

截图单次最多 8 张，单张最多 12MB，总计约 24MB。识别文字可以手工核对修正；没有明确消息归属的截图，不允许跳过核对直接出稿。不能识别的角色不计入统计。

## 数据与隐私

- 数据固定保存在 `%APPDATA%\ChatDraftAssistant\data.json`，独立于安装目录。卸载与重装不会删除该目录。
- 档案、截图（Base64）、消息、分析和全部草稿存本地 JSON；无需联网即可查看历史和档案。复制行为不推断为发送，不生成“已发送”标记。
- Windows API Key 通过 Electron safeStorage 使用系统 DPAPI 加密。界面仅能知道是否配置，不会读回明文 Key；系统安全存储不可用时拒绝明文保存。
- “导出备份”不含 API Key，包含聊天截图等隐私。恢复会先另存当前本地数据，并保留本机 API 设置；跨电脑恢复后请重新配置 Key。
- 识别阶段会向你指定的模型服务发送本轮输入，以及候选联系人的平台、昵称、头像备注，不发送其他人的完整事实档案。拟稿阶段只发送本轮联系人档案快照、聊天及本轮已有草稿。
- 除用户配置的模型 API 请求外，无遥测、自动更新、账号接入或第三方上传。页面禁止远程网络请求、外部导航和新窗口。API 不跟随重定向，只接受 HTTPS（本机回环地址允许 HTTP）。
- 本地聊天档案和截图本身未加密，依赖你的 Windows 账户和磁盘保护。换电脑前请导出备份，不要把 DPAPI 加密 Key 当作可迁移凭据。

## 规则取舍

硬规则内置；本人真实档案在设置页填写并仅在本机保存，设置页也可编辑补充偏好。额外偏好不能覆盖联系人隔离、真实经历、只拟稿和内容红线。

正常情况先分析后给三版，每版两个气泡。冷场/投入失衡时优先执行“不追问、不硬聊”：允许具体、可回应的陈述结尾，覆盖常态开放问题、调皮和多钩子要求。刚认识不损不逗的要求也优先于强行双线交替。对方先告别时可正常回应告别。

统计使用已核对的消息：消息条数、非空白字符数，以及对方最近三条是否只有一两个字。完整消息不少于六条、双方各不少于两条时，检测条数或字数约两倍及以上，或连续长发对短回。样本小只提示证据不足；连续三条极短回复仍立即降档。在线活跃状态不作为强证据。

模型先生成，再经本地格式/常见违规校验及第二次模型审稿。失败最多重试一轮，仍不合格则拦截，不把失败话术存成有效草稿。每次拟稿通常有两次模型请求；截图识别另一次，费用由你配置的 API 服务计算。

## 已知验证边界

已完成单元/集成测试、Linux 下真实 Electron 桌面自动化，以及 Windows PE/NSIS 构建检查。模型测试使用可控模拟响应与本机 HTTP 接口，未使用真实客户 API Key。

尚未在 Windows 10 实机执行安装、DPAPI 保存/重启读取、卸载重装留存验收；也未用真实 Soul/牵手/微信截图接入目标模型验证识别准确率。模型的语义判断、未记录经历识别、开放结尾与语气仍可能出错，二次审稿不能保证绝对零误判。因此这是一版可安装、待实机与真实模型验收的客户端，而不是九项验收已全部通过的声明。

安装包未进行代码签名，Windows 可能显示未知发布者。

## 开发与复现（仅供维护者）

Node.js 24 LTS，执行 `npm ci` 后：

- `npm start`：开发启动。
- `npm test`：核心测试。
- `npm run test:ui`：真实 Electron 界面自动化；Linux 使用无头 Ozone，测试夹具只在未打包且显式 E2E 模式启用，不进入发行包。
- `npm run dist:win`：打包 Windows x64，再通过纯 JS 修改图标/版本资源、直接使用 NSIS 生成安装包，不需要 Wine。构建工具可首次下载 Electron 与 NSIS；应用自身运行不需要这些工具。

主要文件：`src/main.cjs` 桌面安全边界与 IPC，`store.cjs` 本地存储，`service.cjs` 识别/生成流水线，`rules.cjs` 事实、提示词与校验，`api.cjs` 模型请求，`renderer.js` 页面交互，`build/windows.nsi` 安装卸载脚本。
